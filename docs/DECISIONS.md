# Design decisions and deviations

This file records every place where the implementation had to interpret or adapt the build specification
(Section 0, rules 3 and 8). Each entry: **date — what — why**.

## Operational (ops) columns added to the ERD (Chapter Three, Figure 3.8)

These columns are not in the original ERD. They are needed to run the system and can be mentioned in Chapter Four.

| Table | Column(s) | Purpose |
|---|---|---|
| users | `is_active`, `store_code_default`, `last_login_at` | Deactivating accounts (FR16), consent preference (NFR6), statistics |
| submissions | `language_source`, `filename`, `char_count`, `client_ip_hash`, **`store_code`** | Language detection transparency, uploads, statistics, consent for this submission |
| analysis_reports | `public_id`, `status`, `stage`, `error_message`, `ai_explanation_available`, `ai_unavailable_reason`, `ai_unavailable_until`, `llm_provider`, `llm_requests`, `tools_run`, `consistency`, `improved_code_check`, `redaction_count`, **`redaction_by_type`**, `redacted_code`, `sensitive_domains`, **`started_at`**, `completed_at` | Job status/polling, fallback reporting, Transparency tab |
| code_sections | `order_index` | Stable ordering |
| findings | `public_key`, `evidence`, `confidence_reason`, `static_tool`, `static_rule_id`, `ai_assessment`, `order_index` | Transparency of each finding |
| feedback | `feedback_token` | One rating per guest browser |
| system_settings | whole table | Admin-configurable settings (FR16) |
| llm_usage | whole table | Gemini free-tier daily quota tracking (8.9.6) |

Columns in **bold** go slightly beyond the spec's list:
- `submissions.store_code` — the consent choice must survive between the HTTP request and the background job
  that nulls `code_text` (8.20).
- `analysis_reports.redaction_by_type` — the report JSON (Section 9) shows `redaction.by_type`, so it must be stored.
- `analysis_reports.started_at` — `AnalysisStatus.started_at` and the stuck-job clean-up (12.9) need it.

## Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-10-07 | Local development uses **Python 3.13** (the machine has no 3.12); the Docker image uses `python:3.12-slim` as specified. `requires-python = ">=3.12"`. | Only 3.13 is installed on the development PC. No 3.13-only features are used. |
| 2026-10-07 | `make` is not available on Windows, so `tasks.ps1` provides the same targets. The `Makefile` remains the reference (used on Linux/CI/Docker). | Developer machine is Windows 11. |
| 2026-10-07 | **Semgrep is an optional extra (`pip install -e ".[tools]"`)** instead of a core dependency. The Docker image always installs it. | Semgrep has no stable native Windows build; making it a core dependency would break `pip install` on Windows. Runners report `unavailable` when it is missing (8.5.1). |
| 2026-10-07 | WeasyPrint needs the Pango/GTK libraries, which are installed in the Docker image. On a Windows host without GTK the PDF endpoint returns a clear 503 `PDF_UNAVAILABLE` error and the PDF test is skipped. | WeasyPrint cannot load its native libraries on a plain Windows install. |
| 2026-10-07 | `BCRYPT_ROUNDS` setting (default **12**, tests use 4). | Keeps the test suite fast; production cost stays 12 (Section 12.3). |
| 2026-10-07 | Settings values are stripped of `# comment` text if a `.env` parser keeps an inline comment as the value (e.g. `GEMINI_API_KEY=   # free key`). | The `.env.example` in Section 4 has inline comments after empty values. |
| 2026-10-07 | `ESLINT_DIR` falls back to `backend/app/static_analysis/eslint` when the configured folder does not exist. | The `.env.example` value `/opt/eslint` is Docker-specific; this makes local development work without editing `.env`. |
| 2026-10-07 | State-changing API requests with a non-JSON `Content-Type` are rejected with **415** `UNSUPPORTED_MEDIA_TYPE`; requests with no body and no content type (logout, DELETE) are allowed. | Section 12.4 requires rejecting form posts; bodiless requests cannot carry a CSRF form payload. In production the Origin/Referer check also applies. |
| 2026-10-07 | The app runs `alembic upgrade head` itself at startup (idempotent), in addition to the Docker entrypoint. | Starting the server without migrating first crashed with "no such table"; this makes local development one step simpler. |
| 2026-10-07 | Redaction: names containing a keyword but clearly not secrets are skipped (`author…`, `…_url`, `…_type`, `…_label`, `min_…`/`max_…`, camelCase equivalents), as are string values with two or more spaces (sentences). Dict keys in quotes (`"password": "…"`) are also matched. | The literal `auth` keyword in 8.4 would mask `author = "Jane Doe"` and create a false CRITICAL CWE-798 finding on clean code. |
| 2026-10-07 | Java wrapping keeps leading `package`/`import` lines **outside** the inserted `public class Snippet {` line; lines below the wrapper are shifted by 1 (the spec's `line_offset = 1`). | Imports inside a class body are a Java syntax error, so PMD/javalang could not parse wrapped snippets that have imports. |
| 2026-10-07 | PMD is run **without** the RLIMIT_AS/RLIMIT_CPU `preexec_fn`; instead `PMD_JAVA_OPTS=-Xmx512m` bounds the heap and the subprocess timeout bounds CPU time. | The JVM reserves more virtual address space than 1.5 GB at start-up and fails under RLIMIT_AS. |
| 2026-10-07 | Matching findings across tools/runs treats CWE "families" as equal: 259/321→798, 94→95, 77→78, 328→327, 338→330, 396→390, 772→404. | Bandit reports hard-coded passwords as CWE-259 while the redactor uses CWE-798; Semgrep reports bare `except` as CWE-396 while Bandit uses CWE-390. Without this, the same problem appeared twice. |
| 2026-10-07 | Semgrep check IDs of vendored rules are shortened to the rule ID (e.g. `xai-py-eval`); registry rule IDs are kept in full. | Semgrep prefixes local rule IDs with the rule file's dotted path, which is noise in the UI. |
| 2026-10-07 | For Bandit, the curated rule→CWE map of 8.6.3 takes priority over Bandit's own `issue_cwe`; Bandit findings are categorised by CWE (security by default; reliability for CWE-390/396/703/…). | Real Bandit 1.9 output labels `eval` (B307) as CWE-78 and `try/except/pass` (B110) as CWE-703 + security. The spec's map (B307→CWE-95, B110→CWE-390) describes those weaknesses correctly. |
| 2026-10-07 | When the consistency run is **disabled or fails**, AI-only findings get MEDIUM confidence (8.14), with the reason "…was not run" (disabled) or "…could not run" (failed). | 8.11 and 8.14 disagree about the failed case (LOW vs MEDIUM); 8.14 is the more specific rule. |
| 2026-10-07 | "Specific lines" (confidence rule 4) means a finding range of at most 15 lines. | The spec does not define it numerically. |
| 2026-10-07 | For static-only findings, "How to fix" always comes from the built-in recommendation dictionary; the AI's `static_assessment.reason` is appended to "Why it matters" as "AI's comment: …". | The assessment reason explains *why the AI agrees* (e.g. "this is a real SQL injection"); it is not a fix, so showing it as the recommendation would confuse users. |
| 2026-10-07 | The mock provider produces **one AI finding per group** of overlapping static findings with the same CWE (all IDs in `related_static_ids`), not one per static finding. | One finding per static ID made the merge produce duplicate "both" findings on the same lines. |
| 2026-10-07 | The built-in recommendation dictionary lives in `app/pipeline/recommendations.py` and is shared by the mock provider and `merge.py`. | Avoids the real pipeline depending on the mock module. |
| 2026-10-07 | LLM range checks clamp **sections, findings and change line ranges** that are at most 2 lines outside the code (the spec mentions findings only); larger errors still trigger a repair. | Models often end the last section at `line_count + 1`; a repair request would waste free-tier quota for a harmless off-by-one. |
| 2026-10-07 | When the reply was cut off (`MAX_TOKENS`, empty text) the next attempt re-sends the **original** task plus "Keep every explanation short…", instead of the repair template. | The repair template contains only the previous reply; an empty reply gives the model nothing to repair. |
| 2026-10-07 | **Secret values are also masked inside static-tool messages** (`redaction.mask_secrets`) before they are put in the prompt or stored. | Found by the integration test "secrets never reach the LLM": Bandit B105 quotes the password in its message (`Possible hardcoded password: 'Winter2024!Reports'`), which leaked the secret into the static-findings block of the prompt. FR4 requires secrets to be masked before anything is sent to the LLM. |
| 2026-10-07 | Gemini: the installed `google-genai` 2.28 accepts `response_json_schema` (full JSON Schema from Pydantic); it is used instead of `response_schema`. If the API rejects the schema, the client logs once and continues without it (the schema is also in the prompt). SDK retries are disabled explicitly (`HttpRetryOptions(attempts=1)`) so the pacer and daily counter see every request. | Spec 8.9.5 asks for whichever schema parameter the SDK supports; our own retry policy (8.9.3) must control retries. |
| 2026-10-07 | Gemini thinking control tries, in order, `thinking_level="low"` (Gemini 3), `thinking_budget=1024` (2.5), then no thinking config — the first one the model accepts is remembered (`off`: budget 0 → level minimal → level low → none). | The alias `gemini-flash-latest` may point to either generation; the spec says to retry without the setting when it is rejected. |
| 2026-10-07 | New error code **503 `PDF_UNAVAILABLE`** when WeasyPrint's native libraries are missing (Windows without GTK). | Clearer than a 500; the Docker image always has the libraries. |
| 2026-10-07 | Report JSON has a few **additional** fields: `overview.no_review_message`, `overview.ai_unavailable_message`, `improved.has_problems`, `transparency.llm_requests`, `transparency.processing_time_ms`, `transparency.code_storage_note`, `transparency.consistency.reason`. No contract field was removed or renamed. | The UI needs the exact fallback message, the "no review required" sentence and the code-storage note (6.2) without duplicating backend logic. |
| 2026-10-07 | The improved-code diff compares the **redacted** code with the improved code (left pane labelled "secrets masked" when secrets were found). | The model only ever saw the redacted code, so comparing against the original would show every masked secret as a change. |
| 2026-10-07 | `docker-compose.yml` runs the app with `APP_ENV=development` and `COOKIE_SECURE=false` by default (overridable with `COMPOSE_APP_ENV` / `COMPOSE_COOKIE_SECURE`). | Local compose is served over plain HTTP; production settings (HTTPS-only cookies, origin check) would make login impossible at `http://localhost:8000`. Real deployments set `APP_ENV=production`. |
| 2026-10-07 | Tool versions used: ESLint **9.39** (spec `^9`; npm warns that v9 is end-of-life but v10 is outside the spec), eslint-plugin-security 3.0, PMD **7.28.0**, Bandit 1.9.4, google-genai 2.28. | Latest releases of the major versions named in Section 2. |
| 2026-10-07 | Benchmark false-alarm metric counts findings with severity ≥ MEDIUM on P10/J10/V10 **per run** (averaged over runs). | Two runs per sample would otherwise double the count. |
| 2026-10-07 | Until the reviewers' `labelling.csv` is filled, `score_benchmark.py` scores the baseline with a clearly labelled automatic keyword estimate (and system precision with findings matching the ground truth). | Lets the dry run (M13) produce `metrics.md`; the final Chapter Four numbers must use reviewer labels. |
| 2026-10-07 | The final Docker stage uses **`python:3.12-slim-bookworm`** instead of `python:3.12-slim`. | `python:3.12-slim` now uses Debian 13, which has no `openjdk-17-jre-headless`; Debian 12 keeps the Java 17 runtime required for PMD (Section 2). |
| 2026-10-07 | The "Download PDF" button fetches the PDF and shows a message on error instead of being a plain link. | With a plain link, a server error was saved by the browser as `pdf.json`; found by the Playwright e2e test. |
| 2026-10-07 | The SPA catch-all route is exempt from the 120/min default limit. | Loading the frontend (Monaco has many asset files) must not consume the API rate limit. |
| 2026-10-10 | Live Gemini check (M5): `LLM_MODEL=gemini-flash-latest` resolved to **`gemini-3.8-flash`**; P01 analysed successfully (CWE-89, CRITICAL, HIGH, source both). | Spec M5 asks for the resolved model name to be recorded. |
| 2026-10-10 | The Gemini health check (`/api/health`) caches a network/API error for **60 s** instead of 10 minutes, and logs the error type. `ok`, `model_not_found` and auth results are still cached for 10 minutes. | On a slow connection one timed-out check made `/api/health` report `"llm": "error"` for 10 minutes, with nothing in the log, although the key worked. |
| 2026-10-10 | The improved-code diff keeps its Monaco models on unmount (`keepCurrentOriginalModel/ModifiedModel`) and disposes them itself after the editor is gone. | Found by the e2e "all samples" test: the wrapper disposed the models before the diff widget released them, logging "TextModel got disposed before DiffEditorWidget model got reset" when leaving the Improved Code tab. |
| 2026-10-10 | The e2e "no console errors" check ignores only the browser's network log line for the guest `GET /api/auth/me` 401. | The API contract (7.2) specifies 401 for guests and the app handles it; Chromium still logs every 4xx as "Failed to load resource". |
| 2026-10-10 | Free-tier pacing defaults in `.env.example` lowered to **4/min and 18/day**. | Google's free tier for `gemini-3.8-flash` allowed only 20 requests per day per project (quota `GenerateRequestsPerDayPerProjectPerModel-FreeTier`); with 900/day the app kept sending requests that Google rejected with 429. |
| 2026-10-10 | Windows client package: `SETUP-WINDOWS.bat` (venv, packages, optional ESLint, `.env` via `scripts/setup_env.py`) and `START-WINDOWS.bat` (single server on port 8000 serving the prebuilt frontend from `backend/static`). `.\tasks.ps1 package` builds the zip without `.env`, databases, virtual environments or `node_modules`. | The client runs the application on Windows without Docker or a frontend build; the developer's API key and data must not be shipped. |
| 2026-10-10 | The backend serves the SPA from `STATIC_DIR` when it contains `index.html`, otherwise from the repository's `frontend/dist`. | `START-WINDOWS.bat` in the development folder (no `backend/static`) showed "The frontend has not been built" although `npm run build` had been run. |
| 2026-10-10 | Docker run (M12) was first blocked by a slow connection (Docker Hub TLS timeouts at ~3 KB/s); it was completed later the same day when the connection improved. | Network limitation of the development machine, not a code problem. |
| 2026-10-10 | Fixed invalid YAML in `semgrep_rules/javascript.yml` (unquoted `{..., root: $ROOT, ...}` pattern) and added a unit test that loads every vendored rule file with PyYAML, so it runs on Windows too. | Semgrep rejected the whole JavaScript configuration, so no vendored JavaScript rule ever ran; the live Semgrep tests are skipped on Windows, which hid the problem until the Docker run. |
| 2026-10-10 | Semgrep runs **without** the `RLIMIT_AS`/`RLIMIT_CPU` `preexec_fn`; memory is bounded with `--max-memory 1500` (MB) and time by `--timeout` plus the subprocess timeout. Exit codes ≥ 2 are reported as tool status `failed` with Semgrep's first error message. | Under `RLIMIT_AS` 1.5 GB the semgrep-core engine was killed at start-up ("engine was killed … too much memory"); the runner reported this as `ok` with 0 findings, so Semgrep silently found nothing in Docker. Same reason as the PMD decision above. |
